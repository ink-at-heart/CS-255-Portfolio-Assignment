# CS-255-Portfolio-Assignment
### Portfolio Assignment for System Analysis &amp; Design class
<br>
For this class’ Project, we were required to design a system for a client to provide a driving education service to students preparing for their driver’s test. The system was called “DriverPass” and would provide course information and practice tests as well as on-the-road and in-person classes. Students would be able to register and sign up for classes in person, over the phone, or online in the app.
<br> <br>
The first step of system design is problem solving—what is your system going to provide to the user? What problem is it going to solve? Next comes mapping out use cases and figuring out different scenarios of how your system will be used. This helps solidify your general idea into more concrete, testable actions you want the system to be able to do. In the case of this project, the problem being solved is students needing help studying and preparing for their driving test. So the system design revolved around that objective of helping students.
<br> <br>
When coming up with a system design, it’s important to consider the user’s needs because if the system doesn’t fit the user’s needs, they won’t use it. In order to keep your system relevant, efficient, and effective, you have to consider user needs and requirements as part of the system design—and be willing to pivot if/when those needs change. This translation of user requirements into system design was a part of this Project that I did well. I was able to take the given scenario interview between my company and the client company, pinpoint their requirements for the system and what they wanted it to accomplish, and translated that into system objectives, functional and nonfunctional requirements, and a general user interface outline for the system. 
<br> <br>
A part of my project submission that I'd go back and revise is my UML Activity diagram showing the use case of a Student logging in to view their profile, view some coursework, and take a test. At the start of the diagram, I show the login step with a conditional loop for if the Student inputs the correct password. If they do, the continue on to "View Profile". If not, they loop to "Reset Password", then back to the "Login" step. What I would change is add a limitation on the amount of incorrect passwords the Student can input before being looped to "Reset Password" as well as a limitation on the amount of times they can reset their password within a certain amount of time (i.e. 24 hours).
